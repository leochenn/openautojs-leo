# 验证码坐标校准模块需求文档

## 1. 背景
微信小程序会定期更新验证码弹窗布局。现有脚本对数学验证码和滑块验证码的处理依赖固定区域配置，能应对老版本，但新版本中已经出现输入框结构变化、滑块轨道位置变化、图片区域变化等问题。

由于验证码弹窗无法在正式抢票前稳定触发，现有页面预热无法覆盖验证码阶段。因此需要新增 App 内部的验证码校准模块，让用户提前上传数学验证码和滑块验证码截图，并手工框选关键区域，生成当前设备专用的验证码坐标配置，供正式抢票脚本快速使用。

## 2. 核心目标
- 用户能从系统相册或文件选择验证码截图。
- 用户能分别校准数学验证码和滑块验证码。
- 用户能在截图上手工拖拽框选关键区域。
- App 保存当前设备专用的验证码 profile。
- 正式抢票脚本读取 profile，替代旧固定验证码坐标。
- 第一版支持基于当前截图的模拟识别，用于保存前后验证框选是否合理。
- 保留现有 `skipFinalSubmit` 配置，允许正式流程只完成验证码处理但不点击最终确定。

## 3. 非目标
第一版不追求以下能力：

- 不做跨设备通用配置。
- 不内置一份适用于所有用户的验证码布局模板。
- 不要求 App 自动框选关键区域。
- 不解决全新验证码机制，例如点选文字、旋转图片、语义识别等。
- 不把复杂 OCR 或布局识别放到正式抢票瞬间执行。

## 4. 用户流程
1. 用户进入 App 内“验证码校准”模块。
2. 用户选择校准类型：数学验证码或滑块验证码。
3. 用户从系统相册或文件选择对应截图。
4. App 展示截图，第一版只要求基础全屏预览，不要求缩放画布。
5. 顶部展示当前类型需要标注的项目，标注项目单选。
6. 用户选择项目后，在截图上拖拽框选对应区域。
7. 用户完成所有必填项后，点击“模拟识别”。
8. 模拟识别通过，或用户确认接受当前结果后，保存 profile。
9. 校准首页展示数学和滑块两类校准是否已完成。

## 5. 数学验证码标注项
数学验证码中的数学题表达式居中显示，不会随机分布。因此第一版只需要框选表达式区域，不需要额外框选整张验证码图片。

必填项：

- `mathExpressionRegion`：数学表达式 OCR 区域。
- `mathInputRegion`：输入框区域，保存时取中心点作为点击点。
- `mathSubmitRegion`：确定按钮区域，保存时取中心点作为点击点。

可选项：

- `mathPopupRegion`：验证码弹窗整体区域，用于诊断或偏移校验。

数学模拟识别要求：

- 使用 `mathExpressionRegion` 从上传截图中裁剪表达式区域。
- 调用现有数学验证码识别逻辑。
- 展示识别出的原始表达式、计算结果、是否成功。
- 不执行真实输入和点击。

## 6. 滑块验证码标注项
必填项：

- `sliderImageSearchRegion`：大小灰色滑块可能出现的搜索区域。
- `sliderHandleRegion`：黑色箭头或拖动块区域，保存时取中心点作为拖动起点。
- `sliderTrackRegion`：滑动轨道区域，用于正式阶段识别是否为滑块验证码，也可用于保存前校验。
- `sliderSubmitRegion`：确定按钮区域，保存时取中心点作为点击点。

可选项：

- `sliderPopupRegion`：验证码弹窗整体区域，用于诊断或偏移校验。

用户不需要分别框选大滑块和小滑块，只需要框选二者可能出现的搜索范围。现有灰块识别算法继续在该区域内寻找目标块。

滑块模拟识别要求：

- 使用 `sliderImageSearchRegion` 在上传截图中查找灰色目标块。
- 使用 `sliderHandleRegion` 计算拖动起点。
- 输出模拟拖动起点、目标点、识别到的灰块信息。
- 使用 `sliderTrackRegion` 做滑块特征校验。
- 不执行真实拖动和点击。

## 7. 配置保存
校准结果保存为当前设备专用 profile，例如 `captcha_layout_profile.json`。

示例结构：

```json
{
  "schemaVersion": 1,
  "createdAt": "2026-05-21T00:00:00+08:00",
  "deviceWidth": 1440,
  "deviceHeight": 3040,
  "mathProfile": {
    "completed": true,
    "expressionRegion": { "x": 0, "y": 0, "w": 0, "h": 0 },
    "inputRegion": { "x": 0, "y": 0, "w": 0, "h": 0 },
    "submitRegion": { "x": 0, "y": 0, "w": 0, "h": 0 }
  },
  "sliderProfile": {
    "completed": true,
    "imageSearchRegion": { "x": 0, "y": 0, "w": 0, "h": 0 },
    "handleRegion": { "x": 0, "y": 0, "w": 0, "h": 0 },
    "trackRegion": { "x": 0, "y": 0, "w": 0, "h": 0 },
    "submitRegion": { "x": 0, "y": 0, "w": 0, "h": 0 }
  }
}
```

坐标以当前设备截图像素为准。若用户选择的截图尺寸与当前设备屏幕尺寸不一致，第一版应直接提示风险或拒绝保存，避免误用其他设备截图。

## 8. 正式抢票脚本消费方式
正式流程前半段保持不变。点击确认预约后进入验证码阶段：

1. 等待验证码弹窗渲染。
2. 截图一次。
3. 读取验证码 profile。
4. 使用 `sliderTrackRegion` 和 `sliderHandleRegion` 做轻量滑块判断。
5. 若判断为滑块：
   - 在 `sliderImageSearchRegion` 中识别目标灰块。
   - 从 `sliderHandleRegion` 中心点拖动到目标点。
   - 根据 `skipFinalSubmit` 决定是否点击 `sliderSubmitRegion` 中心点。
6. 若不是滑块：
   - 在 `mathExpressionRegion` 中识别表达式。
   - 点击 `mathInputRegion` 中心点。
   - 使用定制 IME 输入答案。
   - 根据 `skipFinalSubmit` 决定是否点击 `mathSubmitRegion` 中心点。

正式阶段不再扫描多套固定区域，也不做复杂布局定位。

## 9. 校验与失败处理
保存前校验：

- 必填区域是否完整。
- 区域宽高是否有效。
- 区域是否在截图范围内。
- 当前截图尺寸是否匹配当前设备屏幕。
- 模拟识别是否能跑通，失败时允许用户返回调整。

正式执行前校验：

- profile 是否存在。
- 数学和滑块 profile 是否都完成。
- 当前屏幕尺寸是否匹配 profile。
- 必填区域是否完整。

校验失败时应明确提示重新校准，不建议盲跑旧固定坐标。

## 10. 第一版范围
第一版包含：

- App 内验证码校准入口。
- 系统相册或文件选择截图。
- 数学和滑块两类独立校准。
- 基础截图展示。
- 顶部单选标注项。
- 拖拽框选区域。
- 保存本机 profile。
- 基于上传截图模拟识别。
- 正式脚本读取 profile。
- 保留 `skipFinalSubmit` 行为。

第一版暂不包含：

- 缩放画布。
- 多步撤销。
- 自动框选。
- 跨设备导入复用。
- 云端模板。
- 复杂可视化编辑器。

## 11. 成功标准
- 用户能在 App 内完成数学和滑块验证码标注。
- 模拟识别能验证框选区域是否基本可用。
- 正式抢票脚本不再依赖老版本固定验证码区域。
- 新版本验证码样本可以通过手工框选生成可用 profile。
- 微信小程序后续仅调整验证码元素位置时，用户重新校准即可，无需修改代码。
